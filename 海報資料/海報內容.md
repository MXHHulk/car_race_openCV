# 循跡自走車專題海報資料

給製作海報的人使用。文字可以直接取用，圖片都在 `圖片/` 資料夾。

**製作前要補上：** 學校、系所、專題名稱、組員、指導老師。文件裡沒有這些資料。

## 一、建議標題

- 主標題：以單鏡頭視覺實現高低差賽道之自主循跡車
- 短版標題：單鏡頭自主循跡車

## 二、一句話介紹

這台車只靠一顆鏡頭，就能在有彎道、岔路、上坡、路口和下坡的賽道上，自己連續跑完兩圈。

## 三、摘要（約 120 字）

本專題以 Jetson Orin Nano 為運算核心，用單一 USB 鏡頭辨識黑底白線賽道，再透過 BMduino 控制前輪舵機與後輪馬達。系統結合 OpenCV 影像處理、Pure Pursuit 轉向控制及各路段專用策略，已連續完成兩圈，最快單圈 87.8 秒。

## 四、研究目標

- 不接電腦、不靠遙控，由車子自己完成賽道。
- 克服上坡、T 字路口與下坡等高低差路段。
- 在穩定的前提下逐步提高速度。

## 五、成果數字

海報建議放大這幾個數字：

| 數字 | 說明 |
| --- | --- |
| **87.8 秒** | 目前最快單圈 |
| **2 圈** | 已達成連續完成圈數 |
| **約 25%** | 一圈時間縮短幅度（117 秒 → 87.8 秒） |

## 六、硬體架構

| 部件 | 功能 |
| --- | --- |
| Jetson Orin Nano | 影像處理與控制決策 |
| USB 鏡頭 | 640×480，約 30 fps，離地約 15 cm |
| BMduino UNO | 接收指令、驅動周邊、失聯自動停車 |
| PCA9685 | 產生舵機與馬達方向控制訊號 |
| DRV1011 | 驅動兩顆後輪馬達 |
| 舵機 | 控制前輪轉向 |

Orin 與 BMduino 以 UART 115200 bps 通訊，每秒傳送 20 次指令，封包含檢查碼。

## 七、系統流程

1. 鏡頭取得畫面。
2. OpenCV 切出賽道區域，找出左右白線。
3. 把畫面座標換算成車身座標，算出中線。
4. 用 Pure Pursuit 算出前輪角度，再依前輪角度決定速度。
5. 需要時交給爬坡、路口、下坡的專用動作。
6. 把指令傳給 BMduino，驅動舵機和馬達。

圖片：`圖片/系統流程圖.png`

## 八、核心技術

| 技術 | 用途 |
| --- | --- |
| 滑動視窗找線 | 從畫面找出左右白線 |
| 地面投影 | 把畫面位置換算成實際距離 |
| Pure Pursuit | 依前方目標點計算轉向 |
| 速度規劃 | 直線加速、彎道減速 |
| 後輪差速 | 幫助車子轉過急彎 |
| 畫面背景估車頭角度 | 不用 IMU，也能控制路口左轉角度 |
| 虛線偵測 | 判斷坡頂路口位置 |

## 九、挑戰與解決方法

海報空間有限時，建議選前四項。

| 路段 | 遇到的問題 | 解決方法 |
| --- | --- | --- |
| 上坡入口 | 差速讓內輪幾乎停轉，車子上不去 | 偵測到變慢就關閉差速、兩輪一起出力 |
| 坡道 | 地面不平，距離換算會失準 | 限制前輪角度，並直接看白線的像素位置 |
| 坡頂路口 | 固定時間轉彎，每次位置都不同 | 偵測虛線，車頭接近才左轉 |
| 下坡 | 畫面上線條雜亂，容易開出賽道 | 維持車頭方向，落地後再固定右轉 |
| 長彎 | 車子一直偏向外側 | 加入累積修正，補足轉向不足 |
| 高速直線 | 速度提高後左右蛇行 | 直線時看遠一點 |

## 十、測試結果

| 版本 | 一圈時間 | 說明 |
| --- | --- | --- |
| 加入速度規劃前 | 約 117 秒 | 平均速度約 33% |
| 加入速度規劃 | 約 100 秒 | 直線 48% |
| 連續兩圈版本 | 約 91 秒 | 連續完成兩圈 |
| 目前最快 | 87.8 秒 | 第二圈尚未跑完 |

圖片：`圖片/圈速變化.png`

**使用時要注意：** 87.8 秒是單圈成績。連續兩圈的紀錄是約 91 秒，不要寫成「連續兩圈 87.8 秒」。

## 十一、開發方法

專題採用「實跑、紀錄、分析、修正」的循環：

1. 每次實跑都把每張畫面的數據存成紀錄，並錄下影像。
2. 比較成功與失敗的圈，找出差異。
3. 修改後先用錄影重播和模擬驗證。
4. 再回到實車測試，並用 Git 保存每個穩定版本。
