一、測試過程

  1. Orin 端環境設定

    pyserial 已安裝；使用者 jetson 加入 dialout 群組；停用並關閉 nvgetty，避免它佔用 UART。

  2. 燒錄 BMduino：一開始上傳失敗

    錯誤訊息：can't enumerate any e-Link32（exit status 30）。原因是 USB 插錯口：插到的那個口在電腦上顯示為 COM7（PID 8069），沒有燒錄要用的 HID 介面。

    改插另一個口後，電腦顯示為 e-Link32（PID 802F，HID + COM6），上傳成功，監控視窗出現 BMduino UART test ready。

  3. 找序列埠

    這台 Orin 沒有 /dev/ttyTHS0，40-pin 的 Pin 8/10 對應的是 /dev/ttyTHS1。程式放在 ~/orin_tools/ 底下，不在 ~/。

  4. UART 通訊測試：通過

    python3 uart_test.py -p /dev/ttyTHS1 -b 115200
    送出 CMD 99 個，收到有效 STA 99 個，無效 0 個 → PASS。接線、鮑率、封包格式、checksum 都正確，兩個方向都通。

  5. 馬達控制測試：通訊正常，但輪子不轉

    python3 motor_cmd.py --bwl 20 --bwr 20 -t 2
    STA 有效 19、無效 0（通訊正常），但後輪沒有轉。

  6. 馬達診斷程式：6 個步驟只有 B2 會轉

二、目前判斷

同一套程式碼，有的腳位能動、有的不能動，所以問題不在程式，在硬體線路或驅動板上。下圖用顏色標出控制路徑上每一段的狀態：

Orin ttyTHS1→ UART →BMduino Serial1
BMduino D9→74LS14→ENB＋IN4 ← PCA CH4→OUT3/4 → 馬達 B
IN3 ← PCA CH3給高電位沒作用 → 馬達 B 不能正轉
BMduino D8→74LS14→ENA＋IN1/IN2 ← PCA CH1/2→OUT1/2 → 馬達 A
綠 已確認正常紅 確認有問題黃 這條路上至少一處有問題，還不知道是哪一處

可能原因

  • 馬達 B 只能單向轉：PCA9685 CH3 → 驅動板 IN3 這條線沒接好或插錯通道，或是驅動板的 IN3 輸入腳壞了。
  • 馬達 A 完全不轉：ENA 這一路（D8 → 74LS14 pin 13 → 6Y–5A 跳線 → pin 10 → ENA）、IN1/IN2 的線、OUT1/OUT2 到馬達的線、驅動板 A 通道，或馬達 A 本身。
  • 電路圖上的 PCA9685 通道，可能和實際接線不一樣。

三、我做了什麼、寫了什麼

orin_tools/uart_test.py原本就有 Orin 端 UART 測試：送出停止指令、驗證 BMduino 回的 STA，最後判定 PASS/FAIL。這次用它測出 ttyTHS1 是正確的埠。
orin_tools/bmduino_uart_test/bmduino_uart_test.ino原本就有 BMduino 端 UART 測試韌體：收到有效的 CMD 就回 STA，並讓 LED 閃一下。不會驅動馬達。
orin_tools/bmduino_motor/bmduino_motor.ino新寫 正式的控制韌體，依協議書實作：解析 CMD（三個欄位都要有、不可重複、需在範圍內、checksum 要對）；用 PCA9685 控制前輪舵機（CH0）與 IN1~IN4，用 D8/D9 的 PWM 調速；每 100 ms 回報一次 STA；上電時馬達停止；超過 500 ms 沒收到有效 CMD 就停車；未完成的封包超過 50 ms 就丟掉。舵機中心、轉角上限、馬達反向、起動死區都可以在程式開頭的設定區調整。目前還沒有在我這邊編譯驗證過。
orin_tools/motor_cmd.py新寫 Orin 端控制程式：BMduinoLink 類別負責送 CMD、解析 STA；有「定值模式」（--fwa --bwl --bwr -t）和鍵盤遙控模式（--teleop，用 W/A/S/D 操作）。預設每秒送 20 次，結束或中斷時會自動送停車指令。已在電腦上驗證 checksum 與協議書範例一致，也能正確處理被拆成兩段的封包，並丟掉 checksum 錯誤的封包。
orin_tools/bmduino_motor_diag/bmduino_motor_diag.ino新寫・已執行 馬達診斷程式：不需要 Orin，自動輪流執行 A1~B3 六個步驟（EN 直接給高電位 / 用 PWM、正轉 / 反轉），用來找出是哪一段出問題。上面那張 6 步驟的結果就是用它測的。
orin_tools/bmduino_pca_scan/bmduino_pca_scan.ino新寫・待執行 PCA9685 通道掃描：ENA/ENB 保持高電位，CH1~CH15 輪流單獨輸出高電位，用來找出 IN1~IN4 實際接在哪個通道。

五、下一步

  1. 杜邦線直接接驅動板（不經過 BMduino）：ENA 接 5V、IN1 接 5V、IN2 接 GND，看馬達 A 會不會轉；馬達 B 用 ENB/IN3/IN4 照做。用來分出問題是在驅動板和馬達，還是在前面的線路。
  2. 目視和電表檢查：PCA9685 CH1~CH4 → IN1~IN4 的杜邦線；74LS14 pin 11–12 的跳線；OUT1/OUT2 的螺絲端子有沒有鎖緊。
  3. 執行 bmduino_pca_scan.ino：確認通道對應；如果只是插錯通道，改程式設定就好。
  4. 把 bmduino_motor.ino 燒回去，用 motor_cmd.py 測前輪（--fwa 20）和後輪。
  5. 馬達能正常轉之後：接上編碼器讀轉速，做 PID 定速控制。
